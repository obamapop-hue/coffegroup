# 운영자 탭과 메뉴·옵션 통합 설정

2026-10-27 구현. Google 반영은 일반 사이트 갱신 명령으로 진행한다.

## 관리 분류

상단에서 카페·판매자, 회원 관리, 사용자 문의, 주문 이력, 개인정보 처리방침을
선택한다. 각 기존 권한 검사와 주소를 유지하며, 주문 이력은
`/accounts/operator/?tab=orders`에서 조회한다. 카페 표와 최근 주문 목록을 같은
화면에 함께 쌓지 않는다. 문의 대화·회원 관리·카페별 메뉴 관리에도 같은 분류를 둔다.
개인정보 처리방침은 계속 운영자 전용 초안이며 공개 정책으로 바꾸지 않는다.

## 메뉴 설정 순서

1. 카페·판매자 표에서 해당 카페의 메뉴·옵션 관리로 이동한다.
2. 상단 ‘설정할 메뉴’에서 기존 메뉴를 선택하거나 ‘메뉴 추가’를 누른다.
3. 한 편집 영역에서 분류·메뉴명·가격·표시 여부와 옵션을 입력한다.
4. 옵션별 이름·선택 방식·필수 여부와 선택 항목·추가금액·기본 선택을 정한다.
   아이스/핫과 샷 추가는 빠른 추가 버튼을 제공하고, 원하는 옵션은 직접 만든다.
5. ‘메뉴·옵션 함께 저장’을 눌러 메뉴와 옵션의 변경사항을 함께 저장한다.

메뉴 이름을 입력하면 기존과 같이 아이스/핫·샷 +0 기본 옵션을 준비한다. 필요 없는
옵션은 삭제할 수 있다. 같은 이름의 빠른 추가 옵션을 반복해서 만들지 않는다.
단일 선택은 기본값 하나만 체크하며 여러 개 선택에서는 여러 기본값을 둘 수 있다.
항목 수가 늘어나면 편집 영역이 아래로 늘어난다. 기존 표 붙여넣기와 옵션 전체 표도
유지한다. 등록·삭제·수정은 저장 전까지 임시 변경이며 변경 취소로 되돌릴 수 있다.

## 자료 보호와 검증

기존 JSON 저장 API의 메뉴·옵션 전체 일괄 검증, 원자적 저장과 버전 충돌 확인을
재사용한다. 오류 시 입력을 유지하고 해당 편집 칸에 표시한다. 판매자의 품절 상태를
덮어쓰지 않으며, 이미 만들어진 주문방의 메뉴판·가격 사본은 수정하지 않는다.
새 DB 구조·외부 서비스·비밀키 등록은 필요 없다.

로컬 전체 앱 검사 229개가 통과했다. 별도 로컬 DB와 Chromium 320/390/1440px에서
실제 CSRF 요청으로 새 메뉴·옵션 동시 저장, 수정·재조회, 단일 기본값, 3개를 넘는
선택 항목, 삭제 취소, 잘못된 금액의 전체 저장 취소, 오래된 창의 충돌 및 기존
주문방 사본 유지를 확인했다.

로컬 PostgreSQL과 Chromium이 준비된 개발 환경에서 재현한다. Google 주소나 실제
회원 자료를 사용하지 않으며 로컬 이외 DB 연결에서는 실행을 거부한다.

```bash
.venv/bin/python scripts/verify_catalog_browser.py
```
