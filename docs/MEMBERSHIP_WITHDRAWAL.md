# 회원 탈퇴·문의 보관 — 2026-10-25

구현·로컬 검증을 마쳤다. Google 배포와 추가 키 등록·실제 카카오 요청 검증은 아직이다.
공개 개인정보 처리방침은 게시하지 않았다. 운영자만 개인정보 안내 초안을 볼 수 있다.

## 이용 흐름

개인정보 → 회원 탈퇴 → 카카오로 본인 확인 → 최종 확인 체크 → 회원 탈퇴하기.
기존 로그인 콜백을 재사용하므로 새 Redirect URI를 등록하지 않는다.
본인 확인은 동일 브라우저·회원에 연결된 1회용 OAuth 상태와 별도 확인값을 검증한다.
다른 카카오 계정의 응답으로 탈퇴하지 않으며, 확인은 5분 동안 유효하다.
일반 로그인이나 역할·권한 변경을 탈퇴 확인으로 사용하지 않는다.

운영자 계정은 즉시 탈퇴하지 못한다. 다른 운영자에게 업무를 넘기고 기존의 서버용
권한 관리 명령으로 운영자 권한을 해제해야 한다. 진행 중인 본인 주문(open/closed/
pending/accepted)이나 카페의 대기/수락 주문이 있으면 해당 주문을 먼저 처리하도록
안내한다. 미전송 주문서는 기존 삭제 기능을 사용할 수 있다.

탈퇴 시 회원·카카오 연결·계정 연결 코드와 회원의 기존 서버 세션을 삭제한다.
판매자 연결은 해제하고 카페를 영업종료로 바꾸며 이력을 남긴다. 주문과 수정 이력의
회원 연결은 NULL로 바꾸되, 주문 당시 총무·참여자 닉네임, 메뉴·옵션·수량·금액과
처리 시각·이력은 변경하지 않는다. 기존 PostgreSQL 주문 보호 규칙을 완화하지 않았다.
이 보존 정책의 적법 근거·기간이 검토 완료됐다는 뜻은 아니다.

## 카카오 연결 해제

기존 로그인용 REST API 키/Client Secret과 별개인 **어드민 키**를 서버에서만 사용한다.
탈퇴 직전에 이 키로 현재 회원을 조회해 연결을 확인한다. 다른 앱의 키이거나 응답을
확인할 수 없으면 회원 삭제를 중단한다. 응답의 개인정보·오류 본문은 보관/출력하지 않는다.

회원 삭제와 연결 해제 재시도 작업 생성은 하나의 DB 거래로 처리한다. 삭제가 확정된
뒤에만 카카오 연결 해제를 요청한다. 카카오 응답 지연/장애 시에는 임시 회원 구분 번호를
작업표에 남기고 1분부터 최대 1시간 간격으로 재시도한다. 임시 작업이 남아 있는 동안
같은 카카오 계정의 재가입을 막는다. 연결 해제 성공 또는 동일 키에서 이미 해제된
응답(-101)을 확인하면 임시 번호와 작업을 삭제한다.

키가 변경되면 이전 키로 확인한 대기 작업을 새 키로 해제 완료 처리하지 않는다.
이 경우 운영자가 같은 카카오 앱의 올바른 키인지 확인해 별도로 처리해야 한다.
운영자 화면에는 남은 작업 수를 표시하지만 회원 구분 번호나 비밀값은 노출하지 않는다.
운영자의 **개인정보 안내 초안 확인 → 탈퇴 연결 확인**은 회원을 삭제하지 않는 조회다.

웹/자동 처리 프로그램에서만 어드민 키를 사용하며, DB 갱신 Job에는 전달하지 않는다.
HTTP 요청은 고정된 Kakao HTTPS 주소에만 전송하고 리다이렉트를 따르지 않는다.
요청당 제한은 8초이며 자동 기한 처리의 한 번 순회마다 최대 1건만 시도한다.

카카오 설정에서 사용자가 직접 앱 연결을 끊었을 때의 외부 통보 처리는 아직 없다.
이 작업으로 그 기능까지 제공하거나 개인정보 처리 준비 전체가 끝났다고 안내하지 않는다.
공식 API 사양 확인 경로: https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api#unlink
외부 API 실제 성공은 사용자의 Google/Kakao 환경에서 별도로 확인해야 한다.

## 문의 보관

사용자가 답변 완료 후 1년 보관·삭제를 선택했다. 최신 답변 완료 시각에서 달력상
1년이 지나면 문의와 모든 답변을 함께 삭제한다. 추가 문의는 답변 대기로 바뀌어
자동 삭제 대상에서 빠지고, 다시 답변한 날부터 계산한다. 대기 문의의 별도 상한은
정하지 않았다. 자동 처리 프로그램은 시작 시와 이후 매시간 이 작업을 수행한다.
주문 기록이나 닉네임을 삭제하는 기능이 아니다. 백업 사본까지 즉시 지우는 것은 아니다.

## Cloud Shell 적용 순서

1. 기존 사이트 갱신 명령으로 DB 구조와 화면을 먼저 반영한다.

```bash
git -C ~/yeongcha pull --ff-only && python3 ~/yeongcha/scripts/gcp_update_site.py
```

2. 카카오 디벨로퍼스 → 앱 영차 → 앱 → 어드민 키에서 실제 값을 복사한다.
키는 채팅에 보내지 않고 아래 명령이 값을 기다릴 때만 붙여넣는다. 입력 문자는 숨긴다.

```bash
python3 ~/yeongcha/scripts/gcp_configure_withdrawal.py
```

도구가 Secret Manager에 보관하고 기존 실행 계정에 이 비밀값의 읽기 권한만 준다.
기존 로그인 키·DB·계정·카페·메뉴를 변경하지 않는다. 로그인 연결 검증을 마쳤거나
실제 탈퇴가 성공했다고 보고하지 않고 사이트 기본 상태만 확인한다.
등록 전에는 탈퇴 버튼 대신 준비 중 안내와 문의 경로를 제공한다.

3. 운영자 페이지 → 개인정보 안내 초안 확인 → 탈퇴 연결 확인을 실행한다.
이는 운영자 회원을 지우지 않는다. 실제 탈퇴는 별도의 카카오 시험 계정으로 확인한다.
운영자 본인 계정을 탈퇴 시험에 사용하도록 안내하지 않는다.

## 확인한 범위

기존 포함 앱 검사 204개와 추가된 운영자 연결 확인 검사 1개, 배포 도구 검사 45개를
통과했다. 탈퇴와 새 주문 생성이 동시에 실행돼도 주인 없는 새 주문이 생기지 않고,
최종 주문 닉네임 수정 방지와 원문 보존이 유지되는지 실제 로컬 PostgreSQL에서 확인했다.
Chromium 320/390/1440px에서 확인 전/후 화면 분리, 실제 CSRF 최종 제출과 연습 회원
삭제·로그아웃, 운영자 전용 초안과 화면 넘침 없음을 검증했다. Kakao HTTP 응답은
시험용으로 대체했으며 실제 Kakao 회원이나 Google DB를 삭제하지 않았다.
