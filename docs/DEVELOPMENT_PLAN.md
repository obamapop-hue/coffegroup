# 단계별 개발 계획

## 2026-10-21 변경 — Google Cloud 이전 우선

사용자가 Railway에서 Google Cloud로 이전하기로 결정하고 이전 계획 작성을
요청했다. 이후의 플랫폼 작업 기준은 [Google Cloud 이전 계획](GOOGLE_CLOUD_MIGRATION.md)이다.
6단계는 구현·로컬 검증 완료, Railway 미배포 상태로 보존하고 새 환경에서 검수한다.
기존 제품 개발 7단계에 앞서 원본 보존·견적, 테스트 환경, 복원/6단계 검수,
최종 전환, 안정화를 한 단계씩 진행한다. 아래 Railway 재배포 대기 기록은
이 결정 이전의 경과이며 Google Cloud 이전 완료를 뜻하지 않는다.

기록일: 2026-10-20. 사용자는 단계별 개발과 진행 보고를 요청했다. 한 단계가 완료되면 결과·검증·남은 문제·다음 범위를 보고하고 멈춘다. 여러 단계를 임의로 한 번에 구현하지 않는다. 사용자 카카오 로그인 성공 확인 후 개인정보 페이지 수정을 요청했고 해당 작업 후 다음 단계 진행을 승인했다. [1단계 결과](PHASE_1.md), [2단계 상태](PHASE_2.md), [3단계 상태](PHASE_3.md), [카카오 설정 가이드](KAKAO_SETUP.md)를 참고한다. 5단계 최종 확인·전송·내용 잠금·수락 전 취소·5분 자동 거절을 구현했다. 사용자가 6단계 시작을 승인해 판매자 합산 주문 조회·수락·거절과 총무 결과 반영을 구현했다. 반복 소리와 일반 웹 알림은 7단계다. [5단계 기록](PHASE_5.md)을 참고한다. [4단계 기록](PHASE_4.md)을 참고한다. 본인이 확인한 연결코드로 운영자·판매자 권한을 연결했고 실계정 화면 이동의 사용자 확인이 남아 있다.

현재 상태(2026-10-23): Google Cloud의 6단계와 추가 메뉴 완료 기능을 배포했다.
사용자는 기존 Railway 프로젝트 삭제를 확인하고 7단계 진행을 승인했다.
7단계 판매자 반복 소리·테스트·PC 화면 알림과 총무 사이트 알림을 구현했으며,
Google 반영 및 실제 판매자 PC/휴대전화 확인이 남아 있다.
[7단계 기록](PHASE_7.md)을 참고한다. 8단계 파일럿 준비는 아직 시작하지 않았다.

## 반드시 유지할 결정

- 하나의 주문방은 하나의 고정된 메뉴판을 공유한다. 총무·참여자의 접속 시각별 메뉴판 분기는 없다.
- 로그인한 판매자의 카페만 신규 링크 생성·최종 전송이 가능하다. 로그아웃 카페 이름 우측에는 ‘영업종료’를 표시한다. 별도 영업 중지 버튼과 연결 감지는 없다.
- 전송 후 5분 미수락 주문은 서버 자동 처리로 DB와 화면 모두 ‘주문 거절 · 5분 미응답’으로 전환한다. 수락만 차단하고 수락 대기 상태를 남겨 두면 안 된다. 거절 이력·총무 알림·판매자 대기 목록 및 반복 소리 해소를 함께 검증한다.
- 주문방 생성 후 30분까지 미전송이면 폐기하고 이력을 남긴다. 마감 후에도 미전송이면 동일하다.
- 최종 전송 후 메뉴·옵션·가격·수량은 운영자를 포함해 누구도 수정하지 못한다. 수락 전 총무 취소는 가능하다.
- 판매자에게는 총무 닉네임·합산 메뉴/옵션/수량/금액·처리 정보만 제공한다. 참여자 정보·개별 주문 내역·총무 전화번호를 판매자 응답에 포함하지 않는다.
- 카페 전화번호·주소는 총무의 카페 선택 및 전송 후 주문서 조회 화면에서 제공한다.
- 카카오 연동은 로그인만 사용한다. 알림톡·문자 발송은 제외한다.
- 하나의 회원 계정이 총무·판매자·운영자 권한을 함께 가질 수 있어야 한다. 총무는 기본 이용 가능, 판매자는 운영자가 카페 연결, 운영자는 지정 계정에 권한 부여한다. 화면과 서버 권한은 역할별로 구분한다. 판매자 입구의 유효한 로그인만 영업 시작으로 처리하며 총무·운영자 로그인은 영업 상태를 바꾸지 않는다. 구현은 2단계다.
- 웹 MVP는 사이트 자체 알림과 판매자 PC 반복 소리·테스트 버튼을 사용한다.
- 앱 푸시 전달망은 Apple APNs·Google FCM으로 확정했다. iOS 최종 전달은 APNs, Android는 FCM이다. 앱 단계에서 토큰·권한·발송 경로·실기기 수신을 검증한다.
- 사진·주문 복사·완료 예정 시간 변경·결제·정산·배달·조건부 옵션은 제외한다.
- 비회원 동의 체크박스가 필수라고 가정하지 않는다. 실제 개인정보 처리의 법적 근거·안내·보유·파기 정책은 실사용자 수집 전 확정한다.

## 제안 작업 단위

| 단계 | 범위 | 완료 확인 |
| --- | --- | --- |
| 1. 실행 기반 | Django·PostgreSQL 연결, 환경변수 분리, 기본 메인 화면, 실행·검증 명령, 의존성 고정 | 현재 개발 환경에서 서버 기동·DB 저장/조회·기본 화면 응답 확인. 실제 카카오 로그인·주문 기능은 아직 없음 |
| 2. 계정·권한 | 실제 카카오 로그인, 총무·판매자·운영자 역할, 카페와 판매자 연결, 로그인 유지·명시적 로그아웃과 영업 상태 | 실제 카카오 계정 로그인, 미연결 판매자 차단, 역할별 접근 제한 확인. 필요한 외부 설정은 이 단계 전에 준비 |
| 3. 메뉴·주문방 | 운영자 카페/메뉴/옵션/기본값 관리, 카페 연락처, 영업종료 표시·링크 생성 차단, 방 메뉴판 고정, 링크·30분 폐기 | 원본 메뉴 변경에도 같은 방 메뉴판 유지, 정확한 만료 안내, 실제 자동 폐기와 이력 확인 |
| 4. 주문 취합 | 비회원 여러 메뉴·수량 제출, 총무 본인 주문·추가/수정/삭제, 합계, 마감 | 모바일에서 실제 취합 흐름 확인. 다른 참여자 정보 비공개, 마감 후 ‘참여할 수 없는 주문서입니다.’ 표시 |
| 5. 최종 전송·자동 거절 | 마감 후 같은 화면에서 전송·개인정보 안내, 주문서 고정, 수락 대기, 수락 전 취소, 전송 5분 자동 거절 | 중복 전송 방지, 원본 변경 차단, 실제 시간 경과로 DB·화면·이력 자동 전환. 판매자 수락 화면은 다음 단계 |
| 6. 판매자 처리 | 자기 카페 합산 주문서, 5분 단위 완료 예정시간과 수락, 1~30자 거절 사유, 총무 결과 반영 | 수락·취소·기한 경합 검증. 참여자 개인정보와 총무 전화번호 비노출. 예정 시간 변경 기능 없음 |
| 7. 웹 알림·화면 마무리 | 판매자 PC 반복 소리·테스트, 총무 사이트 알림, 상태 갱신·재접속 복구, 모바일 사용성 | 실제 PC 소리·다중 대기·거절/취소 시 종료와 휴대전화 화면 알림 확인. 앱 푸시 성공으로 보고하지 않음 |
| 8. 파일럿 준비·배포 | 전체 흐름·권한·시간 경계·재시작·백업 복원, 개인정보 정책, 실제 배포 설정·비용 확인 | 실제 기기 전체 검수와 복구 증거 제시. 플랫폼 최종 선택·유료 사용·운영 배포는 사용자 결정 후 진행 |
| 후속. 앱·푸시 | 앱 방식 검증, 웹 기능 재사용, APNs·FCM, 앱 로그인·알림 권한·토큰 관리 | iOS/Android 실기기에서 전경·배경·잠금 상태 수신, 로그아웃/탈퇴 후 수신 차단 확인 |

테스트는 각 단계에 포함한다. 기능을 모두 만든 뒤 마지막에만 테스트하지 않는다. 자동 거절의 서버 동작은 5단계에서, 판매자 소리 종료까지의 통합 동작은 7단계에서 검증한다. 5·6단계가 끝나기 전 실제 카페 주문에 사용하지 않는다. 파일럿 공개는 8단계 통과 후다.

## 단계별 보고 형식

1. 이번 단계에서 실제 구현한 것.
2. 실행한 검증과 결과, 사용자가 확인할 수 있는 화면·문서.
3. 미구현·실패·외부 설정 대기를 명확히 구분.
4. 바뀐 파일과 중요한 설계 선택.
5. 다음 단계의 범위.

검증되지 않은 기능을 완료라고 보고하지 않는다. 단계 안에서 발생한 문제는 조사·해결하되, 범위를 넘는 제품 기능은 임의로 추가하지 않는다. 한 단계 결과를 보고한 뒤 사용자 확인을 거쳐 다음 단계로 진행한다.

## 운영자 관리 화면 보완

3단계 이후 사용자 요청과 승인으로 카페·판매자 및 메뉴·옵션 관리를 표 방식으로 개편했다. 여러 행 붙여넣기, 검색·필터, 일괄 저장과 오류/충돌 처리, 저장 이력을 포함한다. [구현·검증 기록](ADMIN_SHEETS.md)을 참고한다. 사용자는 표 표시 수정 이후 4단계 진행을 승인했고, 참여자 제출·총무 취합·편집·마감을 구현했다. 사용자가 5단계 시작을 승인해 최종 전송·취소·자동 거절을 구현했다. 사용자가 6단계 진행을 승인해 자기 카페 주문 처리·완료 예정시간·거절 사유·총무 결과 반영을 구현했다. 준비/픽업 완료 상태는 이번 승인 범위에 넣지 않았으며 7단계 반복 소리·일반 웹 알림은 별도 승인 후 진행한다.


## 2026-10-23 사용자 추가 요청: 메뉴 완료와 총무 알림

Google 사이트에서 운영자·판매자·카페·메뉴 및 기본 주문 흐름이 정상 동작한다고
사용자가 확인했다. 이어 판매자 메뉴 완료 버튼과 총무 완료 알림, 카페 선택 화면의
링크 만들기 버튼을 주문하기로 변경하도록 요청했다. 접수 → 메뉴 완료 전환과
수신자별 읽음 상태를 저장하는 사이트 알림을 이번 승인 범위에 추가한다.
완료 예정시간 수정, 픽업 인수 확인 상태는 추가하지 않는다.
APNs·FCM은 앱 전환 단계이며, 판매자 PC 반복 소리·테스트 버튼은 별도 단계다.
[구현과 검증](ORDER_COMPLETION.md)을 참고한다.


## 2026-10-23 8단계 시작

사용자가 7단계 동작을 확인하고 8단계 진행을 승인했다. 카페 시험 운영에 앞서
복구·보안·개인정보·실제 Google 설정과 비용 확인을 진행한다. 로컬 연습용 DB의
27개 표 백업·복원과 수정 방지 검증을 마쳤으며, 실제 Google 확인과 개인정보
안내 준비는 진행 중이다. [8단계 기록](PHASE_8.md)을 참고한다.


### 8단계 후속 결정

비용 확인은 사용자 지시로 미루고 정상 서비스 준비를 우선한다. 운영 주체는 영차,
문의 창구는 사이트 내 문의 접수·답변이다. 이 창구와 운영자 답변을 구현했으며 Google
반영은 아직이다. 과거 주문의 닉네임은 사용자 요청대로 유지한다. 회원 탈퇴·카카오
연결 해제·보유/파기 기준과 공개 개인정보 안내는 별도 미완료 사항이다.
