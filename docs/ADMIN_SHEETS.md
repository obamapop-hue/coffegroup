# 운영자 표 관리

사용자가 카페 메뉴와 판매자 관리의 대량 등록·조회·수정 불편을 지적했고, 표 방식 개편을 승인했다. 참여자 주문 제출 단계는 이번 작업에 포함하지 않는다.

## 사용 흐름

- 운영자 페이지는 카페 한 곳당 한 행이다. 카페명·전화번호·주소·판매자 연결코드를 셀에서 수정하고 닉네임·영업상태를 확인한다. 연결코드는 입력 후 계정을 확인하며, 빈 코드로 저장하면 연결이 해제된다. 카페명 바로 아래에서 메뉴·옵션 관리로 이동한다.
- 카페 관리에는 메뉴·옵션 탭이 있다. 메뉴 행에서 옵션 개수와 기본값을 확인하고 누르면 전체 옵션 표가 열리고 해당 메뉴의 첫 옵션으로 이동한다. 메뉴·옵션 탭으로 이동하면 검색과 필터를 초기화해 전체 행을 보여준다. 새 메뉴에는 저장 전부터 아이스/핫·샷 +0 기본 옵션을 표시한다.
- 행 추가·10행 추가, 검색·상태 필터·옵션 메뉴 필터, 셀 편집, Tab 이동, Enter/위아래 키로 행 이동, 여러 행 TSV 붙여넣기를 지원한다. 메뉴와 옵션은 함께 저장한다. 붙여넣기는 실제 Excel에서 복사한 탭/줄바꿈 형식과 인용된 셀을 처리한다.
- 새 행·수정·삭제 예정 행을 색과 글자로 구분한다. 저장 전에는 DB를 바꾸지 않는다. 저장하면 서버가 등록된 행·옵션·기본값과 최신 버전을 돌려주며 같은 표에서 바로 확인한다. 사용자가 직접 선택한 메뉴 필터는 저장 후에도 유지한다. 필터 적용 여부를 행 수에 표시하고 전체 보기 버튼으로 해제할 수 있다.
- 금액은 정수 원 단위이며 `3,000`, `3,000원`도 처리한다. 붙여넣는 체크 값은 TRUE/FALSE, O/X, 예/아니오 등을 지원한다. 하나 선택 그룹의 기본값 중복, 같은 그룹의 선택값 이름 중복, 음수 금액·미등록 계정 등을 셀 오류로 표시한다.
- 하나라도 오류가 있으면 일괄 저장 전체를 취소한다. 입력값은 브라우저에 유지하며 오류 셀과 안내를 표시한다. 다른 창에서 원본이 변경됐으면 409로 거절해 덮어쓰지 않는다. 최신 내용 다시 불러오기와 변경 취소는 미저장 변경을 버리기 전에 확인한다. 페이지를 나갈 때에도 미저장 내용이 있으면 브라우저 안내가 나온다.
- 메뉴 삭제는 숨김 처리로 기존 데이터와 옵션을 보존한다. 옵션 행 삭제는 원본 옵션에 적용하되 기존 주문방 사본에는 영향이 없다. 카페 기록과 회원 계정은 이 표에서 삭제하지 않는다. 기존 카페 행은 판매자 연결 해제 동작을 제공한다.
- 최근 저장 이력에는 저장 시각과 등록·수정·연결 변경 요약을 남긴다. 계정 연결코드나 인증 키를 이력 문구에 저장하지 않는다.

## 서버 보호

- `/cafes/sheets/cafes/`, `/cafes/<id>/sheet/`, `/cafes/sheets/seller/`는 활성 운영자만 이용한다. JSON 저장은 CSRF가 적용된 POST이며 GET은 조회만 한다. 응답에 캐시 금지를 적용한다. 계정 조회는 닉네임과 연결 카페 정보만 반환하고 이메일·전화번호·카카오 토큰을 반환하지 않는다.
- 기존 행 ID 전체를 검증하며 다른 카페의 메뉴·옵션 ID를 섞거나 기존 행을 누락해 삭제할 수 없다. 요청의 영업상태·품절상태·닉네임 등 조회용 필드는 저장에 사용하지 않는다.
- 메뉴·옵션 저장은 카페 행 잠금으로 주문방 생성·품절 변경과 직렬화한다. 카페 일괄 편집은 중복 코드 검증과 사용자/카페 잠금을 사용하고 연결을 먼저 해제한 뒤 다시 연결해 일괄 판매자 교환도 원자적으로 처리한다. 판매자 변경 카페는 영업종료로 바꾸고 기존과 같은 연결 이력을 남긴다. 연결이 그대로인 카페의 영업상태는 유지한다.
- 사용자 연결 잠금은 PostgreSQL `NO KEY UPDATE`를 사용해 중복 연결을 직렬화하면서 메뉴 저장 이력의 외래키 조회와 교착되지 않게 한다. 실제 두 스레드의 메뉴 저장/판매자 연결 경합을 검증했다.
- 편집 가능한 원본 필드의 해시로 동시 수정 충돌을 검출한다. 판매자의 영업·품절 상태 변화는 편집 충돌로 취급하지 않고 현재 값을 보존한다. 이미 생성된 `Room`과 메뉴판 JSON에는 쓰지 않는다.
- 새 `ManagementChange` 테이블만 마이그레이션으로 추가한다. 기존 카페·회원·메뉴·옵션을 재생성하거나 테스트 값으로 덮어쓰지 않는다. 외부 표 서비스나 프런트엔드 패키지는 추가하지 않았다. JavaScript와 CSS는 운영자 관리 화면에서만 로드한다.

## 검증

- 실제 PostgreSQL 테스트 65개 통과. 일괄 성공/실패 시 원자성, 셀 오류, 기본값/가격 검증, 조회 권한·CSRF, 다른 카페 ID·누락 항목 차단, 동시 수정 409, 영업/품절 상태 보존, 판매자 교환·중복 방지·연결 해제, 메뉴 숨김·옵션 삭제와 기존 주문방 보존을 포함한다.
- Chromium에서 실제 클립보드로 100개 메뉴와 기본 옵션 300행을 한 번에 붙여넣고 저장했다. 등록 결과가 같은 표에 표시됐고 기존 주문방은 원래 세 메뉴만 유지했다.
- 실제 UI로 카페 여러 곳 등록·판매자 연결·셀 오류 시 입력 유지·옵션 동시 저장·기본값 오류 수정·검색·충돌 시 입력 보존·최신 내용 불러오기를 확인했다. 브라우저 JavaScript 오류가 없었다.
- 320·390·1440px에서 카페·메뉴·옵션 표가 본문 폭을 넘지 않고 표 안에서 가로 스크롤되는 것을 확인했다. 데스크톱에는 관리 화면의 폭을 넓혔고 모바일에는 카페명/옵션 메뉴 고정 열과 스크롤 안내를 제공한다.
- 행 수에 따른 표 높이 제한을 제거했다. 두 메뉴의 옵션 7행을 모두 표시하고, 10행 추가 후 17행으로 표가 늘어나며 마지막 행까지 페이지 스크롤로 접근하는 것을 320·390·1440px Chromium에서 확인했다. 표 내부에는 세로 스크롤이 생기지 않는다. 메뉴별 필터 4/7행 표시, 전체 보기·탭 전환 시 7행 복구도 검증했다.
- 로컬 검수용 회원·세션·카페·메뉴·주문서·저장 이력은 검수 후 제거했다. Railway에 가짜 계정이나 검수 데이터를 만들지 않는다.
- Ruff·JavaScript 구문 검사·마이그레이션 차이 없음·DB 쓰기/읽기 검증을 통과했다.
