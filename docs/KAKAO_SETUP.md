# 영차 카카오 로그인 연결 가이드

## Google Cloud 새 환경에서 이어서 연결하기

기존 영차 카카오 앱은 재사용한다. 사용자가 기존 테스트 데이터 가져오기를
생략하기로 해 Google의 계정·권한·카페·메뉴는 새로 등록한다.

- 새 사이트: `https://yeongcha-test-t7e4i53n5q-du.a.run.app`
- 로그인 Redirect URI:
  `https://yeongcha-test-t7e4i53n5q-du.a.run.app/accounts/kakao/login/callback/`
- 기존 앱 → 플랫폼 키 → **REST API 키 상세** → **카카오 로그인 리다이렉트 URI**에
  위 전체 주소를 추가한다. 키의 관리용 이름과 실제 키 문자열은 구분한다.
- 실제 REST API 키와 카카오 로그인용 Client Secret은 Google Secret Manager로
  전달한다. 채팅·스크린샷·Git에 비밀값을 붙여넣지 않는다. 비즈니스 인증용
  Client Secret은 사용하지 않는다.
- Cloud Run 환경변수는 `KAKAO_RESET_API_KEY`, `KAKAO_CLIENT_SECRET`,
  `KAKAO_LOGIN_ENABLED`를 사용한다. 앞의 두 개는 Secret Manager의 비밀값을
  참조하고, 활성화 값 `True`는 직접 설정하는 켜기 값이다.
- 실제 로그인 후 새 Google 계정 연결 코드를 확인해 해당 본인 계정에만
  운영자 권한을 부여한다. 카페 등록 후 같은 계정을 판매자로 연결할 수 있다.

이하 Railway 단계의 설정 기록은 과거 안내다. Google 작업은 Cloud Run과
Secret Manager에서 수행하며 Railway 변수 등록을 다시 요구하지 않는다.

2단계 테스트용 가이드입니다. 카카오 연동은 로그인만 사용합니다. 알림톡·비즈니스 채널·카카오페이 설정은 필요하지 않습니다.

## 1. 개발자 앱 등록

1. [Kakao Developers](https://developers.kakao.com/)에 서비스 소유자의 카카오 계정으로 로그인하고 개발자 등록을 진행합니다.
2. 내 애플리케이션에서 `영차` 앱을 만듭니다. 사업자 정보가 필요하면 소유자의 실제 정보로 등록합니다.
3. 웹 플랫폼 또는 사이트 도메인에 아래 주소를 등록합니다.

   `https://coffegroup-web-production.up.railway.app`

4. 본인 계정으로 먼저 시험합니다. 다른 사람이 시험할 경우 앱의 팀/테스터 설정과 이용 가능 대상을 확인합니다. 일반 고객 대상 파일럿 공개는 후속 단계입니다.

## 2. 카카오 로그인 설정

1. 앱의 카카오 로그인을 활성화합니다.
2. Redirect URI에 다음 **전체 주소**를 등록합니다. 끝의 `/`까지 같아야 합니다.

   `https://coffegroup-web-production.up.railway.app/accounts/kakao/login/callback/`

3. 동의 항목은 **닉네임**(`profile_nickname`)만 사용합니다. 목적 입력란이 있으면 `서비스 내 닉네임 표시`로 입력합니다. 이메일·전화번호·프로필 사진·친구 목록은 요청하지 않습니다.
4. OpenID Connect는 사용하지 않습니다. 카카오톡 채널 연결도 필요하지 않습니다.
5. **앱 → 플랫폼 키**에서 REST API 유형의 키를 엽니다. 목록의 표시 이름은 사용자가 바꿀 수 있는 관리용 이름입니다. 상세 화면 상단 **REST API 키** 바로 아래의 긴 영문·숫자 문자열 옆 복사 아이콘으로 실제 키를 복사합니다. **키 이름(필수)** 입력칸의 이름은 인증 키가 아닙니다.
6. 같은 REST API 키 상세의 **카카오 로그인 리다이렉트 URI**에 위 콜백 주소를 등록합니다. JavaScript 키 상세나 **로그아웃 리다이렉트 URI** 입력란과 구분합니다.
7. Client Secret은 **카카오 로그인용** 값을 사용합니다. 비즈니스 인증용 값은 사용하지 않습니다. Client Secret 사용 상태를 활성화합니다.

공식 안내: [사전 설정](https://developers.kakao.com/docs/latest/ko/kakaologin/prerequisite), [REST API 로그인](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api).

## 3. Railway 변수 등록

[현재 Railway 프로젝트](https://railway.com/project/2ba98b24-c561-4385-8f7e-12523f21ecfc) → **coffegroup-web 서비스** → Variables에서 아래 3개를 한 번에 설정하고 변경 사항을 배포합니다. Postgres 서비스에 넣지 않습니다.

| Railway Name에 직접 입력할 이름 | Railway Value에 넣을 내용 | 입력 방식 |
| --- | --- | --- |
| `KAKAO_RESET_API_KEY` | 위 앱의 REST API 키 문자열 | 카카오 화면에서 복사 |
| `KAKAO_CLIENT_SECRET` | 같은 앱의 카카오 로그인용 Client Secret | 카카오 화면에서 복사 |
| `KAKAO_LOGIN_ENABLED` | `True` | 키가 아니라 켜기 설정이며 직접 입력 |

사용자 요청에 따라 Railway 변수 이름은 **`KAKAO_RESET_API_KEY`**로 사용합니다. 카카오 화면의 **REST API 키**를 복사해 이 변수의 Value에 넣습니다. `RESET`은 영차 서버에서 정한 이름이며 카카오 키 종류를 바꾸는 것은 아닙니다. 기존 `KAKAO_REST_API_KEY`가 있다면 Value는 그대로 유지하고 Name만 `KAKAO_RESET_API_KEY`로 바꾼 뒤 Deploy를 누릅니다. 이름 변경 전후 배포 중에도 동작하도록 서버는 기존 `KAKAO_REST_API_KEY`도 대체 이름으로 지원하며, 두 값이 있으면 `KAKAO_RESET_API_KEY`를 우선합니다.

키·비밀값을 채팅·스크린샷·Git에 올리지 않습니다. 설정을 마치면 **등록 완료 여부만** 알려 주세요. 기존 `DJANGO_SECRET_KEY`, `DATABASE_URL`, Railway 프로젝트 토큰은 바꾸지 않습니다.

처음에는 로그인 비활성 상태로 배포합니다. 실제 키 2개가 없는 상태에서 활성화만 하면 서버가 설정 오류로 시작하지 않도록 차단합니다. 키를 준비하기 전에는 `KAKAO_LOGIN_ENABLED=False`를 유지합니다.

## 4. 첫 로그인과 운영자 연결

1. [영차](https://coffegroup-web-production.up.railway.app)에서 `카카오로 시작하기`를 눌러 본인 카카오 계정으로 로그인합니다.
2. 상단의 본인 이름을 눌러 **개인정보** 페이지에서 **내 계정 연결 코드**를 확인합니다. 이 코드는 비밀번호가 아니며 카카오 ID도 아닙니다.
3. 소유자가 본인 계정임을 확인한 뒤 해당 코드로 최초 운영자를 지정합니다. 첫 가입자를 자동 운영자로 만들지 않습니다.
4. Railway의 같은 웹 서비스 Variables에 `INITIAL_OPERATOR_ACCOUNT_CODE`를 추가하고 값으로 **본인의 계정 연결 코드**를 넣어 배포합니다. 이 코드는 키·비밀번호가 아니므로 개발 담당자에게 알려 주어 설정할 수도 있습니다.
5. 사이트에서 로그아웃 후 본인 카카오 계정으로 다시 로그인하면 최초 운영자 권한이 부여됩니다. 다른 회원의 가입이나 역할 선택으로는 권한이 생기지 않습니다. 이미 운영자가 있으면 이 초기 지정 기능은 추가 운영자를 만들지 않습니다.
6. 운영자 화면이 열리는 것을 확인한 후 `INITIAL_OPERATOR_ACCOUNT_CODE` 변수를 삭제합니다. 지정된 권한은 DB에 유지됩니다.

개발 담당자의 복구/권한 해제용 관리 명령도 있습니다. 필요할 때만 **Railway 웹 컨테이너 안에서** 실행합니다. 로컬 개발 DB에서 실행해도 Railway 계정에는 적용되지 않습니다.

   ```bash
   .venv/bin/python manage.py grant_operator 본인의-계정-연결-코드
   ```

코드가 잘못되었거나 카카오로 가입하지 않은 계정이면 명령이 거절됩니다. `--revoke`는 운영자 권한 해제용입니다. 이 절차를 위해 DB 비밀번호나 카카오 비밀값을 채팅으로 보내지 않습니다.

## 5. 본인 카카오 계정 하나로 세 역할 시험

1. **총무:** 로그인 후 기본 화면을 확인합니다.
2. **운영자:** 로그인 후 하단의 `운영자 페이지 이동`으로 이동합니다. 카페 이름을 등록합니다.
3. 카페의 판매자 연결란에 본인의 계정 연결 코드를 넣습니다. 연결 직후 카페는 여전히 `영업종료`입니다.
4. **판매자:** 기본 주문 화면 하단의 `판매자 페이지 이동` 버튼을 누릅니다. 카페가 `영업중`으로 바뀝니다.
5. 로그아웃하기 전 총무·운영자 화면으로 이동해도 같은 계정이며 카페 영업은 유지됩니다.
6. 판매자로 들어간 세션에서 로그아웃하면 카페는 `영업종료`가 됩니다. 주문방 이력은 개인정보 페이지에서 확인합니다. 참여자의 음료 제출은 다음 단계입니다.

MVP에서는 판매자 계정 1개를 카페 1곳에 연결합니다. 같은 카페의 판매자를 바꾸거나 연결을 해제하면 영업도 종료되고 이전 판매자는 접근할 수 없습니다.

## 로그인 유지와 최소 정보

- 브라우저를 닫아도 유지되는 사이트 세션을 사용합니다. 세션은 1년 유효기간을 두고 요청할 때 갱신합니다. 카카오 액세스 토큰 만료 때문에 사이트에서 자동 로그아웃하지 않습니다.
- 브라우저 데이터 삭제, 쿠키 차단, 계정 이용 중지 등은 별개입니다. 무기한 로그인 보장을 의미하지 않습니다.
- 총무·운영자 입구로만 로그인하거나 로그아웃한 세션은 판매자 영업 상태를 바꾸지 않습니다. 판매자로 로그인한 세션의 명시적 로그아웃이 영업을 종료합니다. 연결 감지·PC 종료 감지·별도 영업 중지 버튼은 없습니다.
- 카카오의 로그인 식별 ID와 닉네임, 서비스 계정·권한·접속 및 연결 이력을 저장합니다. 이메일·전화번호·프로필 사진과 카카오 인증 토큰은 저장하지 않습니다. 실사용자 공개 전 개인정보 처리방침·보유 및 파기 정책을 확정해야 합니다.

## 연결이 안 될 때

- `KOE006` 등 Redirect URI 오류: 등록 주소와 콜백 전체 경로·HTTPS·마지막 `/`를 확인합니다.
- 앱 키/Secret 오류: 같은 앱의 REST API 키인지, Client Secret이 활성화되었는지 확인합니다.
- 닉네임 동의 오류: `profile_nickname` 동의 항목 설정을 확인합니다. 추가 개인정보 동의를 켜서 해결하지 않습니다.
- 연결 시간이 지났다는 안내: 예전 뒤로가기 화면 대신 메인에서 다시 로그인을 시작합니다. 인증 상태는 10분 뒤 만료되고 한 번만 사용할 수 있습니다.
- 판매자 접근 거절: 카카오 로그인 성공과 판매자 권한은 별개입니다. 운영자가 올바른 계정 연결 코드로 카페에 연결했는지 확인합니다.

자동 테스트는 카카오 응답을 모사합니다. **실제 카카오 계정의 동의 화면과 왕복 로그인 성공은 위 설정 후 별도로 확인해야 합니다.**
