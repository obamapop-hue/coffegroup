# 글꼴·크기·굵기

사용자 요청으로 모든 서비스 화면의 글꼴을 Noto Sans KR로 통일하고 기존
크기에서 1pt씩 키웠다. 1pt는 CSS 기준 4/3px이다.

- `site.css`의 `--font-step: 1pt`를 모든 기존 명시적 글자 크기에 더한다.
  반응형 `clamp()` 값도 그 계산 결과에 더하므로 화면 폭과 관계없이 같은
  증가량을 적용한다. 상속받는 글자에는 증가량을 중복해서 더하지 않는다.
- 본문 400, 버튼·레이블·강조 600, 제목·브랜드 700으로 굵기를 정리한다.
- 버튼·입력칸·선택칸·텍스트 영역·계정 코드에도 같은 서체를 적용한다.
- 한글·라틴 기본 글꼴은 미리 불러오고 한자 등 추가 글자는 필요할 때 같은
  서체의 추가 파일을 받는다. 원본 글자 범위를 유지하며 `font-display: swap`으로
  로딩 중에도 내용을 표시한다. 서체 파일·라이선스·출처는
  [폰트 기록](../static/fonts/README.md)에 정리했다.
- 320px 화면의 주문 목록은 글자를 줄이지 않고 열 사이 여백을 조정해
  메뉴·옵션·금액·수정 링크를 표시한다.

서체는 Railway의 정적 파일로 제공한다. 브라우저에 설치된 한글 서체나
Google Fonts 연결에 의존하지 않는다. 기존 밝은 테마·메뉴/주문 데이터와
서버 기한 처리는 유지한다.

## 검증

전체 PostgreSQL 테스트 125개, Ruff·형식·마이그레이션 차이 없음 검사가
통과했다. 별도의 일회용 DB에서 기존 주문 작성·수정·마감·서명 검증·전송·취소와
복사/대체 복사/실패 안내를 확인했다.

Chromium 320·390·1440px에서 홈·총무·개인정보·판매자·운영자·카페 메뉴 관리·주문서·
주문 편집 8개 화면을 검사했다. 이전 CSS를 별도 브라우저 컨텍스트에 적용해
주요 제목/본문/버튼/입력칸/표의 실제 계산 크기가 각각 4/3px 증가하는지 비교했다.
표시되는 글자들의 서체·400/600/700 굵기, 실제 렌더링 폰트가 사용자 설치 서체가
아닌 커스텀 Noto Sans KR인지 DevTools로 확인했다. 모바일 시작 버튼 노출,
표 내부 가로 스크롤, 페이지 가로 넘침 없음과 JavaScript 오류 없음을 확인했다.
한글·라틴 화면에서 추가 글꼴 파일을 요청하지 않고 한자를 넣었을 때 같은 출처의
추가 파일을 불러오는 것도 확인했다. 검수 DB는 전체 제거했고 실제 Railway
주문·회원 자료는 변경하지 않았다.

## 테스트 배포

배포 `94a3e8c3-584c-4d7a-b90b-8b7dbe2a5fd1`가 성공했다. 공개 HTTPS에서 폰트 2개와 CSS 소스 일치, 해시된 preload URL·동일 출처 폰트 요청·장기 캐시, 홈/DB 준비/생존 200·인증/CSRF·카카오 인증 시작과 웹/기한 처리 시작을 확인했다.
