# 개인정보 안내 준비 — 미게시 초안

2026-10-25 코드 확인 기준이다. 실제 운영용 처리방침이나 법률 검토 완료 문서가 아니다.
운영 주체는 영차, 문의 창구는 사이트 내 문의 접수·답변으로 정했다. 보관·탈퇴·파기 기준과 실제 Google 설정을 확인한 뒤 게시한다.

| --- | --- | --- |

카카오 이메일·전화번호·프로필 사진과 액세스 토큰을 DB에 보관하지 않는다.
실제 모델에 빈 이메일 필드가 있다는 사실과 이메일 수집은 다르다.
판매자에게 참여자별 정보와 총무 전화번호를 제공하지 않는 기존 규칙을 유지한다.

## 확정해야 할 내용 (아래 최신 구현 상태도 참고)

- 개인정보 안내에 공개할 운영 주체와 문의 창구.
- 회원 정보의 이용 근거, 보유 기준, 탈퇴·카카오 연결 해제 때의 처리.
- 영구 보존할 주문의 거래 정보와 닉네임 등 개인정보를 구분하는 방법.
  닉네임은 주문 사본과 수정 이력에도 남으므로 회원 행 삭제만으로 지워지지 않는다.
- 비회원의 자유 입력 닉네임과 접속 기록에 대한 안내·보유·파기 기준.
  이름일 수 있는 자유 입력란이 있다는 이유만으로 별도 동의 체크박스가
  반드시 필요하다고 결론 내리지 않는다. 실제 이용 방식과 처리 근거를 검토한다.
- Google의 데이터 보관 위치·처리 위탁·백업과 로그 보유 설정을 반영한 안내.
- 개인정보 삭제 요청 시 백업에 남는 자료의 처리 기준과 재복원 시 삭제 재적용 방법.

미구현인 탈퇴·삭제 기능이 제공된다고 안내하거나, 모든 주문 기록에 일률적인
법정 보유기간이 존재한다고 적지 않는다. 확정된 내용과 실제 구현을 일치시킨 뒤 게시한다.

## 2026-10-25 사용자 답변과 확인 대기

운영 주체명은 영차, 문의용 이메일은 현재 없다고 답했다. 문의 방법은 아직 확정되지
않았다. 과거 주문 닉네임 삭제에 관한 최초 질문을 이해하지 못했다고 답해,
‘총무가 탈퇴하면 그 총무의 과거 닉네임만 탈퇴한 회원으로 바꾸고 메뉴·잔 수·금액·시각은
유지한다’고 다시 설명하고 확인을 요청했다. 이 방식을 승인한 것으로 간주하지 않는다.

### 후속 답변

사용자가 ‘닉네임도 그대로 보관해’라고 답했다. 기존 주문 닉네임은 자동 변경하지 않는다.
이 방식을 선택했다고 해서 보관 목적·기간과 법적 근거 확인이 끝난 것으로 간주하지
않는다. 문의 접수·답변을 사이트 안에서 할지, 새 문의용 이메일을 준비할지 질문했다.


### 문의 창구 확정·구현

사용자가 사이트 안에서 문의 접수·답변을 받기로 결정했다. `/help/`에서 회원과
비회원 모두 문의할 수 있다. 회원 문의는 계정에 연결하고, 비회원 문의는 서버 세션의
무작위 확인값을 해시한 값으로 구분한다. 확인값을 URL에 넣지 않는다. 새 이름·전화번호·
이메일을 요구하지 않는다. 자유 입력 문의에 개인정보가 포함될 수 있으므로 그 내용과
답변의 보관·파기 기준도 처리방침에 포함해야 한다. 문의 보관기간은 아직 확정하지 않았다.

문의는 작성자와 운영자만 각각 허용된 경로에서 조회한다. 판매자에게 제공하지 않는다.
비회원은 작성한 브라우저의 세션이 남아 있어야 답변을 볼 수 있으며, 쿠키 삭제·비공개
창 종료 후에는 확인할 수 없음을 화면에 안내한다. 회원은 재로그인 후 같은 계정으로
다른 기기에서도 조회할 수 있다. 이메일·외부 메시지 알림은 보내지 않는다.

이 창구가 생겼다고 회원 탈퇴·카카오 연결 해제·개인정보 삭제가 자동 처리되는 것은
아니다. 이 기능과 안내·처리 절차는 여전히 남아 있다. 과거 주문 닉네임 보존 요청과
기존 주문 수정 방지는 그대로 유지했다.


## 2026-10-25 탈퇴·문의 보관 구현 상태

사용자가 문의는 답변 완료 후 1년 보관한 뒤 삭제하기로 결정했다. 답변 대기 중 문의는
자동 삭제하지 않고, 추가 문의에 다시 답변하면 그 완료일부터 계산한다. DB의 문의와
답변 삭제를 매시간 처리하도록 구현했다. 백업 사본 즉시 삭제를 뜻하지 않는다.

회원 탈퇴 화면과 카카오 재확인, 로컬 회원 삭제·전체 세션 해제, 주문 연결만 분리하는
처리와 카카오 연결 해제 재시도를 구현했다. 키 미설정 상태에서는 실행을 막는다.
주문 닉네임은 사용자 요청대로 유지했다. 구현·활성화·검증 범위는
[회원 탈퇴 기록](MEMBERSHIP_WITHDRAWAL.md)에 구분했다.

개인정보 안내는 `/accounts/privacy-preview/`에서 운영자만 볼 수 있는 미게시 초안이다.
Google 접속 기록의 실제 보관/처리 위치, 수동 백업의 보유·파기, 과거 주문 닉네임을
계속 보관할 근거와 기간, 개인정보 권리 요청의 실제 처리 절차, 카카오의 외부 연결
해제 통보 처리가 남았다. 운영 주체·문의 경로·문의 1년 기준이 정해졌다고 공개 가능한
처리방침이나 법률 검토가 완료됐다고 안내하지 않는다.


## 실제 서버 보관 설정 조회 준비

사용자가 추가 키 연결과 운영자 화면의 실제 카카오 회원 조회 통과를 확인했다.
실제 탈퇴 성공은 아직 확인하지 않았다. 접속 기록 저장 위치/보유기간, 백업별 실제
저장 위치와 수동 백업 존재 여부는 다음 조회 결과로 확인한다.

```bash
git -C ~/yeongcha pull --ff-only && python3 ~/yeongcha/scripts/gcp_inspect_privacy.py
```

이는 설정 조회만 수행하며 접속 기록 본문이나 회원·주문 자료를 조회하지 않는다.
확인되지 않은 기간을 30일로 가정하거나 SQL 서울 지역만 보고 모든 백업도 한국에
있다고 적지 않는다. 다른 프로젝트나 조직 전체 경로·필터 검토까지 수행하지 않는다.
