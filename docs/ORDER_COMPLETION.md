# 메뉴 완료와 총무 사이트 알림

2026-10-23 사용자가 Google 테스트 사이트 동작 확인 후 요청한 추가 범위다.

- 카페 선택 화면의 링크 만들기 버튼은 **주문하기**로 표시한다.
- 판매자의 접수한 주문에 **메뉴 완료** 버튼을 추가한다. 개별 잔이 아니라
  해당 주문서의 메뉴 전체가 준비됐을 때 누른다.
- `accepted → completed` 전환과 실제 완료시각을 저장한다. 수락 시각과
  완료 예정시간, 최종 메뉴·옵션·수량·금액은 유지한다. 예정시간이 되었다고
  자동 완료하지 않으며 판매자가 직접 누른다. 완료 후에는 완료·거절·취소
  내역으로 이동한다. 픽업 인수 확인이나 완료 예정시간 변경 기능은 추가하지 않는다.
- 주문서 본인에게만 완료 알림을 저장한다. 로그인한 사이트의 어느 화면에서나
  ‘메뉴가 모두 준비됐어요. 픽업해 주세요.’ 알림과 주문서 보기·확인 버튼을 표시한다.
  다른 화면 이동·재로그인으로 없어지지 않고, 확인을 눌러야 읽음으로 기록한다.
- 화면은 5초 간격으로 조회하고 다시 활성화할 때도 조회한다. 브라우저가
  백그라운드 실행을 제한하면 즉시 표시를 보장하지 않는다. 주문 화면을 열어 둔
  총무는 수락 이후에도 상태를 조회해 완료 내용을 자동 반영한다.
- 이번 알림은 사이트 안의 알림이다. 휴대전화 잠금 화면·종료된 브라우저로
  보내는 푸시는 구현하지 않았다. 앱 전환 후 Apple APNs·Google FCM 계획을 유지한다.
  판매자 PC 반복 소리와 테스트 버튼도 별도 단계다.

## 데이터 보호와 검증

Room → Cafe 순서의 DB 잠금 아래 현재 판매자와 영업중 여부를 확인한다.
완료 상태·완료 이력·수신자 알림은 같은 트랜잭션으로 저장한다. 중복 클릭과
동시 요청은 한 번만 성공하며 알림 저장 실패 시 전체를 되돌린다. 다른 판매자는
처리할 수 없고, 총무도 다른 사람의 알림을 조회하거나 읽음 처리할 수 없다.
읽음 처리와 메뉴 완료는 POST 및 CSRF 보호를 사용한다.

마이그레이션 0008은 완료 필드·상태 제약·알림 테이블을 추가하고 0009는 기존
주문 상태 보호 트리거를 확장한다. 수락 대기에서 완료로 건너뛰기, 완료 상태
되돌리기, 완료시각/완료 예정시간/수락시각 재작성과 기존 최종 주문 변경을 차단한다.

검증 결과:

- 실제 PostgreSQL 앱 테스트 161개 통과(신규 완료·알림·동시성 검사 8개 포함).
- Google 배포 도구 검사 28개 통과(일반 갱신의 순서·실패 시 중단 검사 4개 포함).
- 별도 일회용 DB와 실제 Chromium/HTTP/CSRF로 320·390·1440px에서 판매자 완료,
  총무 자동 갱신, 다른 페이지와 재접속 시 알림 유지, 확인 처리와 가로 넘침 없음,
  브라우저 JavaScript 오류 없음을 확인했다. 실제 회원이나 Google DB를 사용하지 않았다.
- Ruff 검사·포맷, JavaScript 구문 검사, 마이그레이션 누락 없음 확인.

## Google 반영

수정본의 Google 반영은 아직 수행하지 않았다. 인증된 사용자 Cloud Shell에서:

```bash
git -C ~/yeongcha pull --ff-only && python3 ~/yeongcha/scripts/gcp_update_site.py
```

소스의 고정 Git 버전으로 Cloud Build를 실행하고 성공한 이미지 digest를 사용한다.
기존 마이그레이션 Job의 이미지만 갱신해 DB 검사까지 통과한 뒤 기존 웹의 이미지만
갱신한다. 카카오·DB·Django Secret, 실행 계정, 연결 주소와 상시 CPU 설정을 재설정하지
않는다. 기존 서비스/Job의 소유 라벨을 확인하며 빌드·마이그레이션 실패 시 웹 갱신을
중단한다. 이는 이전 DB 변경을 자동 되돌리는 기능을 뜻하지 않는다.
