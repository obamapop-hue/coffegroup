# 7단계 — 판매자 주문 알림과 총무 사이트 알림

2026-10-23 사용자가 7단계 진행을 승인했다. 기존 Railway 프로젝트를 삭제했다고
확인했으며 이후 운영 대상은 Google Cloud다. 이 단계의 새 변경은 Google 배포와 사용자의 실제 소리 동작 확인을 마쳤다.

## 판매자 이용 흐름

1. 판매자 페이지에서 **주문 알림 켜기**를 누르고 실제 소리가 들리는지 확인한다.
   **소리 테스트**도 같은 짧은 알림음을 재생하고 주문 알림을 활성화한다.
2. 새 최종 주문이 접수되면 대기 건수와 강조 안내를 표시하고 반복 소리를 재생한다.
   한 건을 수락·거절해도 다른 대기 주문이 있으면 계속 울린다. 취소되거나 5분
   미응답으로 거절된 주문은 대기에서 제거하고, 마지막 대기 주문이 없어지면 멈춘다.
3. PC 화면 알림은 지원되는 브라우저에서 **PC 알림 허용**을 직접 눌렀을 때만
   권한을 요청한다. 거부·미지원이면 화면과 소리를 계속 사용한다. 화면 알림에는
   대기 건수만 포함하며 참여자 개인정보를 넣지 않는다.
4. 수락·거절·메뉴 완료와 새 주문 목록 갱신은 페이지 전체를 다시 열지 않는다.
   원래 audio 요소를 유지하고, 처리 대상 이외의 작성 중인 완료시간·거절 사유와
   포커스를 보존한다. 다른 화면에서 이미 처리한 주문은 작성 중이어도 제거한다.
5. 알림 활성화 의도는 계정·카페별로 해당 탭의 sessionStorage에 보관한다.
   새로고침 뒤 서버의 실제 대기 주문을 다시 확인한다. 브라우저가 자동재생을
   막으면 재생 중이라고 표시하지 않고 **주문 알림 다시 켜기**를 표시한다.
   새 탭에서는 먼저 알림을 켜야 한다. 강제 자동재생이나 영구 음량 제어는 하지 않는다.
6. 연결 오류 시 재확인 안내와 마지막으로 확인한 대기 주문의 알림을 유지한다.
   복구되면 실제 상태를 조회해 정리한다. 로그아웃·권한 상실·페이지 이탈 시 멈춘다.
   알림 준비 상태는 영업 상태를 바꾸지 않는다. 기존 로그인=영업 시작,
   로그아웃=영업 종료 규칙과 서버의 권한·영업중 검사를 유지한다.

PC 음소거·OS 알림 차단·브라우저 종료·기기 절전 상태는 사이트가 해결하거나
감지했다고 표시하지 않는다. 실제 판매자 PC에서 소리와 알림을 확인해야 한다.
이번 PC 화면 알림은 열린 사이트에서 사용하는 Notification API다.
휴대전화 앱 푸시·백그라운드 전달망은 후속 Apple APNs·Google FCM 단계에 남긴다.

## 총무 사이트 알림

기존 메뉴 완료 알림에 수락(고정 완료 예정시간), 거절(사유와 5분 미응답),
미전송 주문서의 30분 자동 폐기 알림을 추가했다. 해당 이벤트가 새로 발생할 때
본인에게만 저장하며 이전 이벤트를 재발송하지 않는다. 읽지 않은 알림은 페이지
이동·재접속 후에도 유지한다. **확인**은 해당 알림의 읽음 상태만 바꾸고 주문 이력은
보존한다. 수락 알림을 읽어도 나중의 메뉴 완료 알림은 별도로 생성된다.

0010 마이그레이션은 기존 완료 알림을 완료 종류로 유지하며 주문별 종류별 유일성을
적용한다. 상태·이벤트·알림은 같은 DB 트랜잭션으로 저장하고, 저장 실패 시 상태도
되돌린다. 최종 주문 내용과 처리 이력의 보호 규칙은 변경하지 않는다.

## 검증과 남은 확인

- 실제 PostgreSQL 서버 테스트 167개 통과. 수락·완료 알림의 독립 읽음,
  거절 사유·정확한 기한·방문 없는 처리의 알림 저장·실패 롤백을 포함한다.
- Chromium의 실제 audio 재생 엔진과 HTTP/CSRF로 여러 대기 주문의 반복 재생,
  다른 주문 처리 후 계속 재생, 마지막 처리 후 종료, 입력 보존, 네트워크 복구,
  새로고침 복구, 다른 탭 처리·로그아웃 후 종료와 320·390·1440px 가로 넘침 없음을 확인했다.
- 별도 브라우저 검사에서 재생 거부를 재현한 뒤 다시 켜기로 복구되는지 확인했다.
  PC 알림 API 허용·거부·닫힘 분기는 모의 API로 확인했다. 실제 OS 알림이나
  실제 스피커에서 소리를 들었다는 의미는 아니다.
- 별도 실제 기한 처리 프로세스를 실행하고 시간을 조작하지 않은 300초 경과 뒤
  거절 DB 상태·대기 목록 제거·반복 소리 종료·총무 알림을 확인했다. 해당 브라우저
  검사는 304초에 통과했고 일회용 DB와 프로세스를 정리했다.
- Ruff·JavaScript 구문·마이그레이션 누락 검사를 통과했다.

검증 도구: 로컬 PostgreSQL과 개발 의존성, Node의 Playwright, Chromium 준비 후
`.venv/bin/python scripts/verify_phase7.py`. 전용 일회용 DB를 만들고 제거한다.
외부 DB 호스트에서는 실행을 거부한다. Google 사이트에 테스트 계정·주문을 만들지 않는다.

Google 배포 후 사용자가 실제 PC 소리·실제 OS 알림·휴대전화 화면 알림을 확인해야
7단계 실기기 검수가 완료된다. 8단계 파일럿 준비는 아직 시작하지 않았다.


## 사용자 확인

2026-10-23 Google 배포 기본 검사 성공 출력을 전달받았다. 사용자는 이후
최소화 상태를 포함해 알림 소리가 모두 정상이라고 확인했다. PC 화면 알림의
실제 OS 표시와 휴대전화 전체 흐름 검수는 별도 확인 사항이다. 8단계는 미착수다.
