# 운영자 카페별 주문 이력

2026-10-27 구현. 운영자 관리의 주문 이력 분류에서 사용한다.
추가 DB 구조나 비밀키 없이 일반 사이트 갱신 명령으로 반영한다.

## 사용 방법

- 카페 이름을 누르면 해당 카페의 주문서만 조회한다. 전체 카페도 선택할 수 있다.
- 회원 이름은 주문한 총무의 닉네임으로 부분 검색한다.
- 주문 날짜는 주문서를 생성한 한국 날짜로 검색한다. 최종 전송 날짜와 다를 수 있다.
- 카페·이름·날짜를 함께 적용할 수 있고, 카페 변경과 페이지 이동에도 이름·날짜를 유지한다.
- 검색 초기화는 이름·날짜를 지우고 선택한 카페는 유지한다.
- 한 페이지에 20개를 최신 생성 시각·번호 순으로 표시한다.

주문서를 열기 전 카페명·생성 시각·처리 상태·총무 닉네임·총 잔 수·총금액을 확인한다.
PC에서는 가로로 정리하고 모바일에서는 카드 안에 정보를 나누어 보여 준다.

## 합계와 닉네임의 기준

전송한 주문은 FinalOrder에 고정한 닉네임·수량·금액을 사용한다. 회원 닉네임이나
카페명이 바뀌어도 전송된 주문 내용은 수정하지 않는다. 카페 분류는 카페 ID로 하므로
카페 이름 변경 후에도 예전 주문을 같은 카페에서 조회한다. 주문서에는 당시 카페명을
표시한다.

전송 전 주문서는 현재 연결된 총무 닉네임과 삭제되지 않은 제출의 합계를 표시한다.
개별 삭제 항목은 합계에서 제외하고, 비어 있는 주문서는 0잔·0원으로 표시한다.
전송 전 오래된 주문에서 회원 연결과 닉네임 원본이 이미 없으면 ‘회원 정보 없음’으로
표시한다. 참여자 별칭이나 다른 회원의 닉네임으로 주인을 추정하지 않는다.
이 기능이 과거에 저장하지 않은 닉네임을 복원하거나 추가 개인정보를 수집하지는 않는다.

## 조회와 검증

기존 운영자 권한·no-store 응답을 유지한다. 검색 값은 폼에서 검증하고 잘못된 조건을
전체 조회로 바꾸지 않는다. 최종 합계 우선 조회와 제출 합계는 SQL에서 계산하며,
목록에 큰 메뉴판 JSON을 읽거나 주문마다 추가 조회하지 않는다.

카페 격리, 복합 검색, 삭제 항목 제외, 0잔, 계정 연결 해제 뒤 확정 닉네임, 카페명
변경, 한국 자정 경계, 잘못된 입력, 페이지 조건 유지, HTML 이스케이프와 조회 수 제한을
검사했다. 전체 앱 검사 236개와 Chromium 320/390/1440px의 실제 카페 선택·조회·
주문서 열기·페이지 이동·초기화·입력 오류 흐름이 통과했다.

로컬 PostgreSQL과 Chromium이 있는 개발 환경에서 재현한다. 이 도구는 별도 로컬
시험 DB만 사용하며 실제 Google 자료를 조회하거나 수정하지 않는다.
