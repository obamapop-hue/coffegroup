# 8단계 — 카페 시험 운영 준비

사용자가 2026-10-23 진행을 승인했다. 이후 사용자 안내에서는 ‘파일럿’ 대신
‘협력 카페 한 곳에서 실제 주문을 받아 보는 시험 운영’이라고 설명한다.
이 단계는 진행 중이며 실제 카페 이용자를 받기 위한 준비 완료로 보고하지 않는다.

## 먼저 확인한 내용

- 기존 주문·권한 테스트와 7단계의 실제 300초 기한 검증 결과는 유지된다.
  실제 Google에서의 장시간 무접속 기한 처리와 재시작·복원 확인은 별도다.
- 운영 설정을 적용한 Django 보안 검사에서 HTTPS·쿠키·비밀키 관련 필수 경고는
  없었다. 공유 Google 주소 전체의 하위 주소/HSTS preload에 관한 두 권고는
  의도적으로 적용하지 않았다. 검사를 통과했다고 보안 문제 전체가 없다는 뜻은 아니다.
- 앱의 웹 접속 로그는 쿼리 문자열을 출력하지 않는다. Google 플랫폼이 별도로
  보관하는 요청 로그·보유기간·접근 권한은 실제 Google 설정 확인이 남아 있다.
- 카카오 계정 구분 번호와 닉네임, 가입·로그인 시각과 자체 계정 연결 코드를
  저장한다. 이메일·전화번호·프로필 사진·카카오 액세스 토큰은 수집·저장하지 않는다.
- 비회원은 자유 입력 닉네임·주문·옵션·수량·시각·중복 제출 방지용 번호를 저장한다.
  서버 접속 기록과 회원/주문 DB의 자료 범위를 구분해 안내해야 한다.
- 주문의 영구 보존과 계정 개인정보 보유·파기는 별도 기준이 필요하다.
  회원 탈퇴 화면과 카카오 연결 해제 처리, 주문 사본에 남은 닉네임의 처리 방식은
  아직 구현/확정되지 않았다. 동의 체크박스가 반드시 필요하다고 미리 정하지 않는다.
  [실제 보유 항목과 남은 결정](PRIVACY_PREPARATION.md)을 참고한다.

## 완료한 복원 연습

실제 운영 자료를 사용하지 않는 로컬 PostgreSQL의 별도 연습용 DB에서 다음을 확인했다.

1. 수락·거절·메뉴 완료·알림을 포함한 가짜 주문을 만들고 실제 pg_dump 백업을 생성했다.
2. 또 다른 빈 연습용 DB에 pg_restore로 복원했다.
3. 27개 표의 모든 행 수와 전체 내용의 SHA-256 비교값이 일치했다.
4. 복원된 DB에서도 최종 주문·고정 메뉴판의 수정 방지 규칙이 작동했다.
5. 연습용 원본·복원 DB를 정리했다. 개발 DB와 Google 자료는 변경하지 않았다.

도구는 `scripts/verify_backup_restore.py`다. 로컬 DB만 허용하며 원격 주소에서는
실행을 거부한다. 이 성공이 Google의 PostgreSQL 18 백업·복원 성공을 뜻하지 않는다.

개인정보 안내에 공개할 운영 주체명과 문의용 이메일을 사용자에게 요청했다.

실제 주문 전체 흐름을 확인하고 카페 시험 운영 시작 여부를 사용자에게 보고한다.

### 생성 명령 정정

사용자의 일반 `gcloud sql instances create`는 `--labels`를 지원하지 않아
명령 해석 단계에서 거부됐다. 이 시도에서 자원은 생성되지 않았다.
위 명령에서 해당 옵션을 제거했다. 이미 원본을 생성할 때 사용한 일반 명령의
지원 옵션만 사용하며, 이 이유로 alpha/beta 명령으로 전환하지 않는다.
임시 자원은 정확한 별도 이름과 사용자의 생성 결과를 확인해 관리한다.

## 2026-10-25 우선순위 변경·서버 안정화 보완

사용자가 비용은 당분간 점검하지 않고 금액과 관계없이 정상 서비스 준비를 우선하도록
지시했다. 비용 확인과 기존 월 예산은 현재 작업을 차단하는 조건으로 사용하지 않는다.
요금제나 청구 설정을 임의로 바꾸지는 않았다.

자동 기한 처리가 살아 있는지 운영 준비 응답에서 확인하도록 보완했다. 성공한 처리
시각을 서버 실행별로 기록하고, 60초 이상 갱신되지 않으면 준비 응답을 503으로 바꾼다.
같은 버전의 다른 서버나 이전 실행의 기록이 실패를 숨기지 않도록 웹/작업 프로그램이
공유하는 실행별 구분값을 사용한다. 판매자 PC 상태나 카페 영업 상태를 감지하는 기능은
추가하지 않는다. 기존 로그인/로그아웃 영업 규칙은 유지한다.

Google 일반 갱신 도구는 새 DB 구조 적용 뒤 웹에 이 준비 검사와 시작/생존 검사를
연결한다. 시작은 5초 간격 최대 24회, 시작 후는 30초 간격 연속 3회 실패 시 Google이
다시 시작하도록 설정한다. SDK가 해당 옵션을 지원하는지 빌드 전에 도움말로 확인한다.
기존 비밀값과 카카오 설정을 덮어쓰지 않는다. 이 운영 보완은 Google 반영 전이다.

400/403/404/500 오류 화면을 한국어로 만들고 내부 오류 내용을 표시하지 않는다.
500 화면은 DB 조회 없이 렌더링할 수 있고 주문 중 오류가 났으면 내 주문에서 상태를
먼저 확인하도록 안내한다.

기존 앱 회귀 검사와 추가 운영/오류 화면 검증, 배포 도구 검사 39개를 확인했다.
별도 연습 DB에서 실제 기한 처리 프로그램을 껐다 켜고 웹 방문 없이 밀린 폐기/거절이
처리되고 이력·알림이 한 번씩 저장되는지 확인했다. 이 재시작 검사는 남은 시간을 짧게
설정한 것으로, 실제 30분이 흐르는 검사를 새로 했다고 보고하지 않는다.

운영 주체명은 사용자 답변에 따라 영차로 기록했다. 문의용 이메일은 없으며 다른 문의
접수 방법이나 새 이메일 준비는 미정이다. 회원 탈퇴 시 과거 총무 닉네임만 ‘탈퇴한 회원’으로
바꾸는 예외를 쉬운 말로 다시 설명해 확인을 요청했다. 아직 답변/승인은 없으므로
탈퇴·닉네임 변경이나 고정 주문 보호 규칙 완화는 구현하지 않았다.

### 사용자 답변 반영과 최종 검증

사용자가 탈퇴 뒤 과거 주문의 닉네임도 그대로 보관하라고 명시했다. 닉네임 변경
예외를 추가하지 않고 기존 주문 보호를 유지한다. 회원의 로그인 정보 정리와 과거
주문 보관의 구체적인 안내·기간/근거는 별도 정리 사항이며, 이 답변만으로 개인정보
보관이 법적으로 검토 완료됐다고 안내하지 않는다. 문의 접수는 사이트 안 문의/답변과
새 문의용 이메일 준비 중 선호를 물었고 아직 답을 받지 않았다.

운영 보완은 앱 검사 175개, 도구 검사 39개와 별도 무방문 재시작 검사에 통과했다.
공개 상태 확인 경로 두 개는 Google 내부 요청의 Host 헤더에도 응답하며, 일반 경로의
허용 주소 검사는 그대로 적용한다. 오류 화면은 요청 문맥을 사용하지 않아 DB 장애나
잘못된 Host에서도 안전하게 표시되고 캐시하지 않는다. 실행별 상태 확인에는 같은
버전의 다른 서버가 고장을 숨기지 않는 검사도 포함했다.
이 보완의 Google 반영과 문의/회원 정보 처리 준비는 남아 있다.


## 2026-10-25 사이트 내 문의 접수·답변 구현

사용자가 문의 창구로 사이트 내 접수·답변을 선택했다. 모든 화면 하단의 문의하기와
개인정보 페이지의 내 문의·답변 확인을 연결했다. 제목·내용으로 접수하고, 본인 문의의
답변과 추가 대화를 볼 수 있다. 운영자 페이지에는 사용자 문의 확인과 답변 대기 수가
표시되며 대기/완료/전체 목록, 답변과 재문의 처리를 제공한다.

회원은 자기 계정으로 다른 기기에서도 조회할 수 있고, 비회원은 작성한 브라우저에서
조회한다. 다른 계정·브라우저의 문의 번호를 알아도 조회/답변할 수 없다. 새 연락처는
요구하지 않고 확인값은 URL에 노출하지 않는다. 비회원의 쿠키 삭제·비공개 창 종료 시
재조회 불가를 화면에 안내한다. 중복 전송은 한 번 저장하고, 오래된 답변 재전송으로
새 재문의가 답변 완료로 바뀌지 않도록 했다. 문의/답변은 원문을 덮어쓰지 않고 추가한다.

검증: 실제 PostgreSQL 앱 검사 185개, 배포 도구 검사 39개, 실제 Chromium의
320/390/1440px 문의 작성·타인 접근 거부·운영자 답변·추가 문의·가로 넘침 확인이
통과했다. DB 구조 누락 검사와 운영 정적 파일 수집도 통과했다. 브라우저 검사 도구는
최초에 입력란의 실제 콜론이 포함된 이름을 빠뜨려 실패했고, 정확한 이름으로 수정한
뒤 통과했다. Google 자료는 변경하지 않았다.

일반 갱신 명령으로 문의용 표와 앞서 준비한 자동 처리 상태 검사·복구 설정을 함께
적용한다. 이 변경들은 아직 Google 반영 전이다. 반영 뒤 사용자가 문의하기로 접수하고
운영자 페이지에서 답변한 뒤 같은 문의에서 답변을 확인한다. 8단계 전체 완료는 아니며
개인정보 처리방침·보유/탈퇴·카카오 연결 해제 처리와 실제 Google 최종 확인이 남아 있다.
비용 확인은 사용자 지시에 따라 계속 미루며 현재 서비스 준비를 차단하지 않는다.


## 2026-10-25 회원 탈퇴·문의 1년 보관 구현

사용자가 개인정보 안내·탈퇴 작업을 승인하고 문의는 답변 완료 후 1년 뒤 삭제한다고
확정했다. 회원의 카카오 재확인·탈퇴 확인·로컬 삭제·기존 세션 해제와 서버 연결 해제
재시도, 진행 중 주문/운영자 계정 보호를 구현했다. 과거 주문과 닉네임을 유지하고
계정 연결만 끊으며 기존 SQL 수정 방지는 유지한다. 문의 자동 삭제도 연결했다.

운영자 전용 개인정보 안내 초안과 회원을 삭제하지 않는 탈퇴 연결 확인 버튼을
제공한다. 공개 처리방침은 게시하지 않았다. 보관 근거·서버 기록/수동 백업 기준과
카카오 외부 연결 해제 통보는 미완료다. [적용 순서와 검증 범위](MEMBERSHIP_WITHDRAWAL.md).

앱 204개 전체 검증 후 추가한 운영자 조회 검사까지 탈퇴 관련 17개를 다시 확인했고,
배포 도구 45개와 실제 Chromium 320/390/1440px 연습 회원 삭제를 검증했다.
새 모델 누락 검사·운영 파일 수집도 통과했다. Google/Kakao 실제 반영·어드민 키 등록과
외부 요청 검증은 아직이다. 사용자 기존 계정이나 Google 주문을 삭제하지 않았다.


## 2026-10-25 실제 보관/위치 조회 결과 수신

사용자가 gcp_inspect_privacy.py의 전체 성공 출력을 전달했다. 조회만 실행했고
설정·원본 자료·비밀값을 변경하지 않았다. 확인한 범위는 현재 프로젝트의 경로와
global/서울 로그 저장소이며 조직 전체의 모든 경로나 필터를 조사한 것으로 확대하지 않는다.

| 항목 | 확인된 값 | 해석 범위 |
| --- | --- | --- |
| 웹/DB 지역 | asia-northeast3 | 서울 |
| 자동 DB 백업 | 활성, retainedBackups=7, COUNT | 최근 7개, 7일과 다름 |
| 조회된 자동 백업 | SUCCESSFUL 3개 | 당시 목록의 개수이며 향후 7개까지 쌓임 |
| 별도 수동 백업 | 1792849041384, ON_DEMAND, SUCCESSFUL | 복구 시험에서 쓴 사본, 자동 7개 보관과 별도 |
| 조회된 백업 위치 | 모두 asia | 특정 국가나 서울 저장으로 확정하지 않음 |
| DB backupConfiguration.location | null | 고정 위치 미지정, 실제 각 백업의 location을 참고 |
| 기본 로그 저장소 _Default | global, 30일, 잠금 없음, ACTIVE | 조회된 저장소의 보관 설정 |
| 필수 로그 저장소 _Required | global, 400일, 잠금 있음, ACTIVE | 모든 주문/접속 기록을 400일 보관한다는 뜻이 아님 |

| 회원 탈퇴 설정 | 활성, 어드민 키 비밀값 참조 연결 | 실제 카카오 조회는 사용자 확인 완료, 실제 탈퇴 시험은 별도 |

운영자 전용 개인정보 초안의 서버 기록·백업 부분에 이 값을 반영했다. `global`과
`asia` 표기만으로 저장 국가를 꾸며 쓰지 않는다. 이 문구 변경의 Google 배포는
아직이며 다음 사이트 갱신 때 적용된다. 닉네임 보관 근거·국외 처리 안내·수동 백업
보유 기준·복구 뒤 개인정보 삭제 재적용·외부 카카오 연결 해제 통보는 여전히 남아 있다.
공개 처리방침이나 8단계 전체 완료로 보고하지 않는다.
